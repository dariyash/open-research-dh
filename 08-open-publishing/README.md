Prepare the project for public release: publish outputs openly, and check and improve their alignment with the **FAIR** principles.

## Learning outcomes
By the end of this module you will be able to:
- Publish research outputs openly.
- Apply an assessment tool to check a project for reproducibility and alignment with the FAIR principles.
- Revise and implement feasible changes.
- Prepare research materials for responsible sharing, appropriate licences, access conditions, metadata,
 and documentation.

## Theory, publishing outcomes openly
Open scholarship finishes by giving your work a permanent, citable home. Key ideas:
- A **DOI** (Digital Object Identifier) makes your output findable and citable forever.
- **Publish the dataset you *created*, not the one you downloaded**, your cleaned, filtered, or enriched
 version (added fields, reconciled entities, merged sources). If your data is simply the unchanged source
 collection, link to that source instead of re-publishing it. This distinction matters both legally and
 as a scholarly contribution.
- **FAIR:** *Findable* (rich metadata, a DOI), *Accessible* (retrievable openly), *Interoperable* (open
 formats, shared vocabularies), *Reusable* (clear licence and documentation).
- **CARE** remains the ethics companion to FAIR, consider rights, communities, and responsibilities
 before opening data.

## Tutorial: publishing on Zenodo
The full step-by-step guide is in [`zenodo_tutorial.md`](zenodo_tutorial.md). In brief:
1. Register on **Zenodo** (https://zenodo.org) and start a **New upload**.
2. Upload your **created** dataset (one project = one Zenodo record = one DOI; several related files can
 go in one record).
3. Fill in the metadata, title, authors, description, keywords, **licence**, richer metadata means more
 *Findable*. Add a link back to your GitHub project.
4. **Publish** to mint the DOI.
5. Add the DOI/link back into your GitHub README so code and data point at each other.

## Guided task
1. Assess your project with the **FAIR Data Self-Assessment Tool** (ARDC).
2. Fix the gaps through your Zenodo metadata and upload; publish the dataset.
3. Re-assess to confirm the improvement, and update your GitHub README with the link(s).

## Self-check
- Why publish your *created* dataset rather than the original download?
- What makes a record *Findable* and *Reusable* in practice?
- Which licence will you apply, and why?
